# Fitness67 — проект для Android Studio и iOS

Общая логика и интерфейс написаны на React Native / TypeScript. Android-оболочка — Kotlin, iOS-оболочка — Swift. Папки `android` и `ios` уже созданы: это исходный нативный проект, а не ссылка на сайт и не APK с WebView.

## Посмотреть готовую работу

Готовый установочный файл находится в комплекте как `Fitness67.apk`. Скриншоты и галерея идут отдельно, запускать эмулятор для просмотра не требуется. Тестовый APK подписан стандартным отладочным ключом и предназначен для личной установки/демонстрации. Для публикации в Google Play нужен собственный release-ключ и отдельная подготовка.

Поддерживаемые процессоры текущего APK: **arm64-v8a** (современные Android-телефоны) и **x86_64** (эмулятор/некоторые устройства). Минимальная версия Android — **7.0, API 24**. На iPhone APK не устанавливается.

## Установить APK на Android

1. Скопируйте `Fitness67.apk` на телефон и откройте его из «Файлов»/«Загрузок».
2. По запросу Android разрешите установку приложений из выбранного источника.
3. Нажмите «Установить», затем откройте Fitness67.
4. Для камеры и уведомлений разрешения выдаются при использовании этих функций.

Приложение не требует Expo Go, компьютера или Metro для обычного запуска. Дневник, рецепты, вода, заметки и вес сохраняются локально. Для Open Food Facts и нейросети нужен интернет; для нейросети дополнительно требуется сервер с ключом API. Источник калорий в справочнике — усредненные ориентиры.

## Открыть работу в Android Studio

1. Распакуйте **всю** папку проекта, сохранив `App.tsx`, `src`, `package.json` рядом с `android`.
2. Установите Node.js 24.3+ и в **корне проекта** выполните:

   ```sh
   npm ci
   ```

3. В Android Studio выберите **Open** и откройте папку **`android`** внутри проекта.
4. В настройках Gradle выберите **JDK 21**. Версия Android Studio должна поддерживать **Android Gradle Plugin 9.2.1** и **Gradle 9.4.1**.
5. В SDK Manager установите Android SDK Platform **37.0**, Build-Tools **37.0.0**, NDK **27.1.12297006**, CMake **3.22.1**. Если Gradle предложит скачать компоненты, согласитесь. Путь SDK Android Studio сохранит в локальный `local.properties`; этот машинный файл в архив не включен.
6. Выполните Gradle Sync. В **Build Variants** выберите вариант **release**, чтобы собирать автономный APK со встроенным JavaScript.

Сборка из терминала, без эмулятора:

```sh
# Из корня проекта, после npm ci
cd android
./gradlew assembleRelease
# Windows:
# gradlew.bat assembleRelease
```

Результат: `android/app/build/outputs/apk/release/app-release.apk`.

Для разработки можно выбрать debug и запустить Metro (`npm start` из корня). Debug-разработка и автономный release — разные режимы; готовый APK в комплекте не требует Metro.

## Что изменено в навигации

Вместо тесной строки с отдельным пятым значком «+» сделаны четыре равномерные вкладки: **Дневник / Прогресс / Блюда / Профиль**. У каждой есть подпись, одинаковая область нажатия и заметное активное состояние. Кнопка **«Добавить»** находится отдельно в верхней части экрана. Переключение раздела возвращает его в начало.

## Демонстрационные данные

По умолчанию дневник пустой. Для наглядного просмотра откройте **Профиль → Пример заполненного дневника → Подтвердить**. Примеры заменят локальные данные — перед этим экспортируйте важные записи. В заголовке будет явно указано «Демонстрационный дневник». Эти записи не являются вашими измерениями или результатом нейросети.

## iOS

Исходники iOS включены в `ios/`. Нативная сборка и подпись требуют macOS, Xcode и вашего Apple Developer signing.

```sh
npm ci
npx pod-install
open ios/Fitness67.xcworkspace
```

Выберите Team в Signing & Capabilities, устройство или симулятор и собирайте в Xcode. Для TestFlight доступны инструкции EAS в `README.md`. В Linux-окружении подписанный IPA не создавался, запуск на iPhone не проверялся. Android Studio собирает Android-часть; iOS собирается Xcode, общие функции используют тот же `App.tsx`.

## Фото еды

Экран фото и серверный код включены. Для реальных оценок нужен развернутый HTTPS-сервер `server/ai.mjs` с `OPENAI_API_KEY` и `FITNESS67_ACCESS_TOKEN`. Настройка приведена в `README.md`. Ключ не вшивается в приложение. Без подключения кнопка оценки недоступна и объясняет причину. Оценку нейросети пользователь проверяет и может исправить.

## Что проверено в этой работе

- Gradle `assembleRelease`: **BUILD SUCCESSFUL**, SDK 37.0, Build-Tools 37.0.0, target SDK 36, min SDK 24.
- Подпись APK Scheme v2 проверена `apksigner`; внутри есть встроенный `index.android.bundle`, ARM64 и x86_64 библиотеки.
- APK установлен в Android 7.0 / API 24 x86_64, приложение запущено без Expo Go и Metro.
- В нативном приложении открыты четыре раздела, загружен пример дневника, создан и сохранен рецепт, изменена порция и добавлена запись, включена светлая тема. После остановки процесса и повторного запуска восстановлены семь записей дневника. В проверенном сценарии нет фатальных ошибок AndroidRuntime / ReactNativeJS.
- Основной PDF и папка `screenshots/android` содержат 10 снимков непосредственно из установленного APK. Дополнительные снимки веб-рендера лежат отдельно.
- TypeScript и 13 модельных/серверных тестов пройдены. Браузерный сценарий добавления/редактирования/удаления еды, воды, заметок, рецепта, веса и темы пройден.
- Пакет JavaScript для iOS экспортируется. Нативная iOS-сборка не выполнялась: macOS/Xcode в окружении нет.

Эмулятор работал без аппаратного ускорения. Первый автоматический контроль после перезапуска использовал слишком короткую фиксированную паузу; повторная проверка с ожиданием готового интерфейса подтвердила восстановление данных. Полный журнал прилагается к материалам.

Реальная камера, внешние приложения для экспорта, фоновые уведомления на конкретном телефоне и реальные запросы OpenAI требуют отдельной проверки на устройстве/с подключенным сервером. Ключ API и AI-сервер в текущем APK не настроены.
